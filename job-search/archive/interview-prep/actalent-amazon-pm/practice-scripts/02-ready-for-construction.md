# "What are your criteria for confirming a project is ready for construction?"

## Say it like this

So for me, knowing a project's ready to start construction comes down to running through a readiness checklist, and then the schedule is the thing that ties it all together.

The first piece is design. The drawings have to be issued for construction, not still sitting in design development, and they've got to be coordinated across all the disciplines, so the architectural and the MEP aren't clashing with each other. Tied to that, the scope has to be fully defined. I don't want open assumptions floating around when we mobilize.

Then permits. Either I've got them in hand or I've got a clear path to them, and I know which ones the scope triggers. So building, mechanical, electrical, fire, plus any special ones like a high-pile storage permit or the seismic permit for the racking.

Then the money side. The budget's approved, the contracts are executed and bought out, and we're ready for notice to proceed. And the long-lead procurement is locked, so the big equipment is on order and I know the lead times actually fit inside the schedule.

And for a retrofit specifically, I want the existing conditions and the phasing worked out. So if there's a team or equipment already in the space, the downtime windows are agreed with them, and the shutdown and tie-in sequence is planned.

And then the schedule is really where I pull all of that together. The way I see it, if I can build a credible, resource-loaded schedule with no open assumptions in it, that's my signal we're ready. A schedule with holes in it is just a list of questions nobody's answered yet. So once every one of those inputs has a real date behind it, that's when I know we're good to go.

## If they dig in

- The formal name for this is a **construction readiness review**, and the upstream discipline is **front-end planning / scope definition** (the CII tool is the PDRI, used at the Gate 3 go/no-go). You can drop "I'd run a readiness review against a definition checklist" to sound program-level.
- Your "50% of the budget spent by ~70% of the timeline" rule of thumb is a **cash-flow / spend S-curve**. Name it that way and it reads as a discipline, not a gut feel.
